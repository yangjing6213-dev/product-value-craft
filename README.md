# 产品价值与场景创作 · product-value-craft

帮助 AI 创作者在策划产品、写介绍和准备推广素材时，把“给谁用、解决什么事、实际能做到哪一步”讲清楚。

产品做出来了，介绍却只剩“高效、智能、强大”；标题、视频和封面各说各话，甚至把还没做的功能写进了卖点。这套指南让 AI 先核对产品事实，再围绕一个具体场景完成你需要的内容。

## 一、这个项目是什么？

这是一个 **Skill：一套让 AI 按照特定方法完成任务的操作指南，需要配合支持它的工具使用。** 本仓库提供文字指南、参考材料和 Codex 显示配置，没有独立的软件界面，也不内置图片或视频生成引擎。

你提供产品现状、目标用户、已有材料和本次要做的东西；AI 据此梳理使用场景，区分已有能力与未来建议，再完成策划、命名、文案或素材方案，并检查它们是否互相矛盾。

只改一句标题，就处理这句标题；已有明确方向，就沿着这个方向继续，不需要每次重做整套定位。

## 二、先看效果

仓库保存了“录课转文案”的[示例输入](examples/lesson-transcript/input.md)和[完整输出](examples/lesson-transcript/output.md)。**这是一次真实的 AI 文字试跑，产品设定为虚构；没有生成图片、成片或实现建议功能。**

| 这次做了什么 | 具体内容 |
| --- | --- |
| 提供材料 | 为小课老师整理录课的工具设定：Windows 导入单个 MP4、生成带时间戳的文字稿、导出 TXT；首次识别需下载模型，结果需人工校对 |
| 提出任务 | 给下一阶段建议，并准备标题、网站首屏、15 秒视频脚本、封面和插画提示词 |
| 得到结果 | 一份围绕“录完课，准备笔记文字底稿”的方案，区分软件处理、老师校对与外部排版 |

输出中的首屏标题是：

> 录完一节课，先把笔记的文字底稿备好。

它没有把导出文字稿说成“自动完成图文笔记”，也没有把 15 秒片长说成识别耗时。你可以复制[完整示例输入](examples/lesson-transcript/input.md)试用，再对照输出检查这些条件是否保留；措辞不必完全一致。

## 三、适合谁用？

### 特别适合

- 做小工具或个人产品，需要把功能介绍改成用户看得懂的用途说明。
- 经常写落地页、推广脚本、封面文案，希望多份素材表达同一件事。
- 已有产品方向，想检查首次使用流程、必要条件和宣传承诺是否对得上。

### 不适合

如果你需要下载后直接打开的软件、自动生成成片的引擎，或保证销量的营销公式，这个项目不能满足。它需要可读取 Skill 的 AI 工具；制作真实图片、视频或网站还需要相应工具与素材。初学者可以从下面的文字示例开始。

<a id="outputs"></a>

## 四、你会得到什么？

按你的请求，可以得到产品改进建议、项目名与标题、页面文案、视频脚本、视觉制作提示词，以及相关的事实核对结果。不会要求每个任务都交付全套内容。

这些产物通常以可复制的文字或 Markdown（带标题、列表的文本格式）出现在对话里，可继续修改。需要文件时，告诉 AI 保存的文件名和位置，并确认文件已生成；本 Skill 没有固定输出目录，也不会自行创建结果库。

图片和视频的提示词是制作材料。实际成品需交由当前环境可用的专业技能及工具完成，并另行检查。

## 五、它能帮你解决什么问题？

| 原来容易卡住的地方 | 这套方法怎么处理 | 仍需你完成的事 |
| --- | --- | --- |
| 有功能列表，却说不清何时有用 | 从一个具体任务写到可得到的结果 | 提供真实功能与使用条件 |
| 每份素材都要重新解释产品 | 复用同一份事实，分别组织文字与画面 | 确认素材适合发布渠道 |
| 宣传容易多承诺一步 | 核对当前能力、人工步骤与待开发建议 | 亲自核实功能、数据和最终内容 |

它提供可复用的判断方法；目前没有证据支持节省多少时间或提高多少转化率的承诺。

## 六、安装与快速开始

### 使用前准备

**必需：**能正常对话并读取本地 Skill 的 Codex 环境，以及可用的账号与模型访问。本仓库未指定最低 Codex 版本；系统支持与账号条件以你使用的 Codex 客户端为准。指南本身是文本文件，不需要安装 Python、Node.js 或其他运行库。

**可选：**需要真实图片、视频或网站时，再准备对应工具、素材和权限。Codex、模型和外部制作服务可能有订阅或用量费用；MIT 许可不包含这些费用。

### 推荐方式：下载后放入 Codex 用户技能目录

下面以 **Windows 文件资源管理器**为例，无需输入终端命令。目标目录是 `~/.agents/skills/product-value-craft`，其中 `~` 表示你的用户文件夹。

1. 打开[本仓库](https://github.com/yangjing6213-dev/product-value-craft)，点击 **Code → Download ZIP**，下载并解压。打开解压后的文件夹，确认能直接看到 `SKILL.md`、`references` 和 `agents`。
2. 在资源管理器地址栏输入 `%USERPROFILE%` 并回车。依次进入或新建 `.agents`、`skills`，再新建 `product-value-craft` 文件夹。若已有同名目录，先备份和比较内容，不要直接覆盖已有修改。
3. 把第 1 步中包含 `SKILL.md` 的那一层内容复制进去。最终应是 `.agents/skills/product-value-craft/SKILL.md`；不要多套一层解压目录。保留 `references`、`agents` 和示例文件。
4. 回到 Codex，新建对话并发送下面的示例。Codex 通常会自动发现新技能；未出现时，检查目录层级后重启 Codex。目录规则与发现机制见 [OpenAI 官方技能说明](https://learn.chatgpt.com/docs/build-skills)。

macOS / Linux 也使用用户目录下的 `.agents/skills/product-value-craft`；需在支持该系统的 Codex 环境中使用。本文没有提供跨系统实测保证。

**下载文件不等于安装完成，放对目录也不代表每个任务都会选用它。** 首次使用请明确写出技能名：

```text
使用 $product-value-craft，只为以下虚构产品写一个标题和一段首页介绍：
“录课转文案”面向整理自己录课的小课老师，在 Windows 上导入单个 MP4，
生成带时间戳的文字稿并导出 TXT。首次识别需下载模型，结果需人工校对。
没有自动排版、自动剪辑或发布功能，也没有速度和准确率测试数据。
```

第一次试用无需替换内容。确认对话中有选用或读取本技能的记录，再查看回复：应得到标题和介绍，并保留下载模型、人工校对的条件。完整任务和参考结果见[示例目录](examples/lesson-transcript/)。

## 七、如何使用？

开始新任务时，先给产品事实和本次交付要求。把下面方括号里的内容换成自己的资料：

```text
使用 $product-value-craft。
产品是：[名称与当前已实现的能力]。
用户在这个时候需要它：[具体场景]。
需要保留的条件：[设备、费用、人工步骤等]。
已有材料：[粘贴说明，或提供可读取的文件]。
这次只做：[例如网站首屏标题、副文案和一个按钮文案]。
已有方向：[需要保留的名称、风格或定位]。
```

继续已有任务时，在同一对话补充：“保留已确认事实，把标题改得更口语；正文控制在 100 字内。”产品能力变了，先说明变动，再要求同步调整素材。

安装后，Codex 也可根据任务描述选用技能；你不必每次记名字，但需要明确使用时可以写 `$product-value-craft`。这是 Codex 的技能机制，不能据此保证其他 AI 平台自动识别，参见[官方说明](https://learn.chatgpt.com/docs/build-skills)。

要真实成品时，明确提出“生成封面图片”或“制作视频”，同时提供素材与要求；AI 还需使用相应制作工具，不能把提示词当成已完成的图片。

<a id="workflow"></a>

## 八、项目工作流程

提供事实与目标 → AI 找到具体使用场景 → 核对能力与条件 → 完成本次产物 → 检查前后承诺 → 你核实、调整并保存。

AI 负责整理、创作与一致性检查；你负责补充无法从材料确认的事实、决定关键取舍，并检查最终内容。现有资料足够时直接开始，关键依据缺失时应标明或补问。对外发布前仍需人工复核，Skill 不会自动获得发布权限。

## 十、注意事项与常见问题

| 遇到的现象 | 可能原因与处理办法 |
| --- | --- |
| Codex 找不到技能 | 检查 `SKILL.md` 是否多套了一层目录；按安装步骤确认位置，未刷新时重启 Codex |
| 已安装，但这次没有选用 | 任务可能不匹配描述；确有需要时显式写 `$product-value-craft`，纯翻译或内部修复通常不必调用 |
| 只拿到脚本，没有成片 | 脚本是文字产物；明确成片要求，并确认环境有可用制作工具、素材与权限 |
| 文案出现材料里没有的功能或数字 | AI 输出需要核对；指出无依据表述，要求依据现有事实修正，发布前再检查 |
